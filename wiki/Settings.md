# Настройки

Полный справочник по разделу **Настройки** веб-интерфейса.

---

## Вкладка «Основные»

| Настройка | Описание |
|---|---|
| **Адрес TM** | Полный адрес TorrentMonitor с протоколом, например `http://torrent.test.ru/`. Используется для формирования ссылок в уведомлениях и RSS-ленте. |
| **User-Agent** | Строка браузера, с которой TM ходит на трекеры. Обычно достаточно значения по умолчанию; менять имеет смысл, если трекер начал отклонять запросы. |
| **Оформление** | Тема интерфейса: Светлое, Тёмное или Классическое. |
| **Включить вход по паролю** | Требовать пароль для входа в веб-интерфейс. Отключайте только если TM недоступен никому, кроме вас. |
| **Включить уведомления** | Глобальный выключатель уведомлений; открывает вкладку «Уведомления». |
| **RSS лента** | Отдавать RSS-ленту обновлений по адресу `/rss/`. |
| **Автоматическое обновление TM** | Автоматически обновлять TorrentMonitor при выходе новой версии. В Docker обновление обычно выполняется обновлением образа — см. [Обновление](Updating). |
| **Режим отладки** | Подробный журнал работы движка — включайте при разборе проблем. |

## Вкладка «Смена пароля»

Новый пароль + подтверждение. Пароль по умолчанию `torrentmonitor` — смените его
при первом входе.

## Вкладка «Уведомления»

Видна при включённом тумблере «Включить уведомления».

| Настройка | Описание |
|---|---|
| **Отправлять уведомления об обновлениях** | Сообщения о новых сериях и обновлённых раздачах: выбираете сервис и адрес. |
| **Отправлять уведомления об ошибках** | Сообщения об ошибках (не удалось войти на трекер и т.п.): сервис и адрес могут отличаться от уведомлений об обновлениях. |

Форматы адресов для каждого сервиса (Telegram, E-mail, Pushover…) —
на странице [Уведомления](Notifications).

## Вкладка «Прокси»

| Настройка | Описание |
|---|---|
| **Использовать прокси** | Включает глобальный прокси для всех запросов к трекерам. |
| **Тип прокси** | HTTP или SOCKS5. |
| **IP и порт сервера** | Например `127.0.0.1:9050`. |

Прокси можно задать и индивидуально для конкретного трекера — через `config.xml`,
см. [Прокси и зеркала](Proxy-and-Mirrors).

## Вкладка «Торрент-клиент»

| Настройка | Описание |
|---|---|
| **Управлять торрент-клиентом** | Включает передачу раздач в клиент. Без этого TM только складывает `.torrent`-файлы в каталог `torrents/`. |
| **Торрент-клиент** | Deluge, qBittorrent, SynologyDS, TorrServer или Transmission. |
| **Адрес торрент-клиента** | Полный адрес с протоколом, например `http://127.0.0.1:9091`. |
| **Логин / Пароль** | Учётные данные веб-интерфейса клиента (у Deluge — только пароль). |
| **Директория для скачивания** | Куда клиент сохраняет файлы, например `/var/lib/transmission/downloads` или `C:/downloads`. Путь указывается так, как его видит **клиент**, а не TorrentMonitor. Если оставить пустым, клиент использует собственные настройки (qBittorrent — папку по умолчанию или папку категории). |
| **Категория по умолчанию** | Только для qBittorrent: категория, назначаемая раздачам, у которых не задана индивидуальная категория. |
| **Удалять раздачи из torrent-клиента** | При обновлении темы старая раздача удаляется из клиента (файлы остаются). |
| **Удалять файлы старых раздач** | Удалять и файлы старой раздачи. Работает только для lostfilm.tv, baibako.tv и newstudio.tv. |

Подробности по каждому клиенту — на странице [Торрент-клиенты](Torrent-Clients).

## Вкладка «Расширенные»

| Настройка | Описание |
|---|---|
| **Таймаут HTTP-запросов** | В секундах; применяется при опросе трекеров и работе с торрент-клиентом. Увеличьте, если трекеры отвечают медленно (например, через TOR). |
| **FlareSolverr / Byparr URL** | Адрес [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr)/[Byparr](https://github.com/ThePhaseless/Byparr) для обхода защиты Cloudflare, например `http://byparr:8191`. Пустое поле — не используется. |
| **Текстовое поле `config.xml`** | Расширенная конфигурация в XML: зеркала трекеров и индивидуальные прокси. Примеры — на странице [Прокси и зеркала](Proxy-and-Mirrors). Кнопка «Помощь по этой настройке» открывает встроенную справку. |

## Вкладка «API»

Генерация API-ключа для [REST API](API) и [интеграции с Sonarr](Sonarr-Integration).

- **Сгенерировать ключ** — создаёт ключ; повторная генерация **инвалидирует старый ключ**,
  и все клиенты API (включая webhook в Sonarr) нужно будет обновить.
- Авторизация запросов: заголовок `Authorization: Bearer API_KEY` или параметр `?token=`.

Краткая шпаргалка по методам API отображается прямо на вкладке;
полный справочник — на странице [API](API).
